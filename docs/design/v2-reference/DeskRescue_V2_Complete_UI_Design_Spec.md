## 1. 全局设计系统（所有六页共用）

### 1.1 氛围与美术

- **基调**：休闲小游戏、治愈轻松、Q 版卡通、暖木维修小屋、薄荷色墙面、绿色防静电垫、奶油羊皮纸、少量金色奖励光效。
- **风格一致**：同一个小修理工（白/米色扳手帽、深色头发、蓝绿色工装、暖肤色），首页欢迎、玩法页提示、单单结算竖拇指、终局举扳手欢呼；表情/手势变化允许，但**角色身份、帽子、服装、肤色与线条风格不变**。
- **设备风格**：已有 19 种设备及线头/端口/清洁设备应复用、增修；有明确轮廓、微描边、柔和厚度影，禁止退化为方块文字、系统 emoji、通用工程图标。设备保持可辨识且比背景抢眼。
- **装饰原则**：墙上的工具、盆栽、咖啡杯、剪纸、螺丝、贴纸不参与命中；不要假装支持互动。低端机以少量静态图/内置 Tween 为主，不堆重型动态模糊或粒子。

### 1.3 字体、层级与文案

- Logo：独立原创可商用图形或可验证版权的字形，中文标题居中大且粗；可用组合位图，不使用未经许可的第三方字体。
- 订单标题：设计像素 40–46；订单指令 21–23；状态数字 28–32；槽位与线头标签 18–22；底部气泡 20–25；结算主标题 48–56；分数 54–62。
- 文字在 `390×844` 等比缩放后必须易读；必要时调整纸签布局而不是强迫小到 10px；不能靠不合理拉伸解决溢出。
- 数据标签简洁：**每处信息只表达一次**；不要同时展示文本星星与 Sprite 星星、两条相同清洁百分比、三种重复的进度提示。
- 全中文正式操作文案；“COZY REPAIR SHOP”只可作小型装饰英文品牌标，不得成为主信息。

### 1.4 坐标系（强制统一）

本文表格坐标 `x,y,w,h`：设计画布左上 `(0,0)`，`x` 向右、`y` 向下；不是 Cocos 的 `Node.position`。从场景的真实 `Canvas`、StageHost、父节点、UITransform、锚点/旋转、Fit 规则测量转换。**视觉层绝不应重置已验证的核心坐标、目标/输入根或吸附半径**。

历史设计映射参考（**必须实测校准**）：StageHost 局部中心拟落在画布 `(360,755)`；若恰好成立，则 `screenX=360+localX`、`screenY=755-localY`。如本地场景不同，先保住原输入节点的世界坐标，再适配底板和周边 UI。

### 1.5 屏幕适配与触摸边界

- 设计画布 `720×1280`；优先检视桌面 Preview `390×844`，其次 `768×1024`、`1280×720`。屏幕宽高比变化时，**外层工坊背景 Cover/延展填边**，**核心操作区等比缩放**，不得横向拉伸导致触摸与图像错位；宽屏可在中间保持竖屏游戏区，两侧延展纯装饰。
- 设计安全预留 `Y=0–112/120` 和底部 `Y≈1220–1280`；它们仅为预设，未来平台安全区需以真实窗口 inset 为准。**不要画可点击的假微信/抖音系统胶囊**。
- 主交互图形和逻辑命中框可分离：例如音效开关可见 76×56，但需给透明可点容器提供约 ≥88×88 设计像素的实际命中面积，保留安全区边界；开始/下一单按钮具有充足触摸面积。
- 任何静态装饰禁止事件监听或 `BlockInputEvents`，不得挡住 drag/cable/clean 的输入层；只有**激活时的结果遮罩**可以拦截下层游戏触摸。所有 hitbox 仍以当前 Stage/元素根为准。

### 1.6 交互与动画节奏

| 触发 | 美术反馈 | 不得破坏 |
|---|---|---|
| 首页加载 | Logo 0.35s 缓入；工坊轻弹入；角色小幅待机；按钮轻呼吸 | 首页期间未开始计时，未激活 Stage |
| 按下主按钮 | 下压 4–6 设计 px、缩放 0.97、约 0.12–0.16s | 点击同步防重，只有一次状态切换 |
| 订单切入 | 悬浮纸签轻入 0.20–0.25s | 原 RunController / Stage 初始化时机 |
| 拖拽拾取 | 继承 0.10s、scale×1.06；装饰阴影提起 | 原坐标、Touch ownership、锁输入 |
| 拖拽正确 | 0.15s 吸附后才计数；槽位青绿亮/勾 | 一次完成回调，不先加分 |
| 拖拽错误 | 0.18s 回位，珊瑚短闪 | 失误一次；CANCEL 不记失误 |
| 连线正确/错误 | 圆润线身、动态端点、成功亮灯/失败回弹 | 保留对应连线、Touch/CANCEL、generation |
| 擦拭 | 灰尘自然淡出 0.08s，露出设备 | 32 格逻辑、28 格阈值、空白不扣失误 |
| 单张结算 | 结果卡 0.92→1、星星依次点亮、分数轻跳字 | 只展示冻结结果，计时停止 |
| 最终结算 | 奖杯/横幅/角色/轻彩纸短促庆祝 | 单次总结果，低端机不过量动画 |

所有视觉 Tween 必须自有、可停止；reset/next/replay/home/disable/destroy 时停止过期视觉回调，绝不触发实际计数与业务结算。已有七类音效与真实音效开关继续复用，不为逐格清洁增加刷屏音效。

### 8.1 双按钮的真实状态迁移（本轮必要新代码）

当前 Day 5A 已有终局 `playAgain()`，**但没有验证过从终局返回首页后再次开始**。必须在当前实际 `LevelManager` 与 `HomeController` 中增量设计，不直接改私有状态或复制第二套管理器。

```text
FinalSummary / DemoComplete
    ├─ 点击「重新挑战」
    │    -> 同步锁按钮 -> 调用现有 playAgain()
    │    -> Stage reset + 结果清空 -> Order1/Stage1 重新开始计时
    │    -> 不再闪现首页
    └─ 点击「返回首页」
         -> 同步锁双按钮 -> 停止结算/粒子/装饰 Tween
         -> 隐藏结算并停用 Stage、暂停 RunController
         -> 复位本轮会话状态/重置结果（不能继续跑旧轮）
         -> 显示 HomeOverlay，重置首页启动门禁
         -> 音效当前 session 设置保留
         -> 再按「开始维修」仅启动一次新 Order1/Stage1
         -> 首页等待期间绝不计时、无活动 Stage
```

返回首页后不得让旧 `LevelManager.startFirstOrder()` 的 one-shot/`initialized` 门禁阻止新一轮开始；应以明确的公开回家/重新开局 API 完成，保持 lifecycle、generation、防双击、残留动画和回调所有权正确。实现逻辑的结构以最新本地源码为准，**不可凭这份设计直接强制指定不存在的成员名**。
